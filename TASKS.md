# Refator MCP Discord — auth dual flow

Cada tarefa = 1 commit. Cada `claude -p` nasce com contexto vazio, então toda info essencial está aqui ou nos arquivos do repo (`src/transport.ts`, `src/envalid.ts`, `src/config.ts`, `README.md`).

**Estado atual (errado):** servidor anuncia `.well-known/oauth-authorization-server` com `grant_types_supported: ["client_credentials"]`. Cliente OAuth do Claude (CC e claude.ai) só fala `authorization_code` + PKCE + dynamic registration — bate 404 em `/authorize`.

**Estado alvo:** dois caminhos de auth coexistem.
1. OAuth Authorization Code + PKCE + dynamic registration → Claude Code / claude.ai.
2. Bearer estático via env `MCP_STATIC_BEARER` → Cursor / Cline (clientes que aceitam token colado, sem discovery OAuth).

**Single-user:** `/authorize` auto-aprova sem tela de consentimento. Storage in-memory (`Map`/`Set`). Sem persistência. Não logar `access_token`, `code`, `code_verifier`, `code_challenge`.

**Cuidados gerais:**
- `/oauth/token` body pode chegar como `application/x-www-form-urlencoded` ou JSON (ambos middlewares já montados).
- `redirect_uri` deve bater strict (não substring).
- `crypto.createHash().digest("base64url")` precisa Node ≥ 16 (suporta).
